# Project rules

Every rule here is checked by `bun run check`. If a check and this file disagree, the check wins.

## Layout

- `src/core/` works with no blocks: request context, logging, errors, analytics, consent, security headers.
- `src/blocks/<name>/`, `src/routes/(<name>)/`, `e2e/<name>/`: a block's three places. A block imports
  only core, `src/gen/` and the blocks in its `block.json` `requires`. Core never imports a block.
- `src/gen/` is generated by `bun run blocks:sync`. Never edit it; change a `block.json` or a block's
  `layer.ts`, `errors.ts`, `events.ts`, `nav.ts`, `viewer.ts`, `auth-plugins.ts` or `workflows.ts`.

## Code

- Effect for everything on the server. Services are `Context.Service` classes with a static `layer`.
  Errors are `Schema.TaggedError` classes in the error channel, each listed in its block's
  `errors.ts` with a status and a safe message. Validation is Effect Schema; zod is banned.
- No `throw`, `try/catch`, `process.env` or `Effect.run*` outside the edges listed in
  `cf-saas-lint.json`. Server functions and server routes run effects through `runEffect` /
  `runResponse` from `src/core/run-effect.ts`.
- Every outside call is an `Effect.tryPromise` inside `Effect.fn("Name.method")` or piped through
  `Effect.withSpan`.
- Log with `Effect.log*`, never `console`. Every line already carries the request id and user.
- Every flow a user can see, and every lifecycle, is an XState machine in a `*.machine.ts` file with a
  unit test. Machines that drive UI live in a `ui/` folder and also need `e2e/**/<name>.paths.spec.ts`.
- New user-visible outcomes get an analytics event in the block's `events.ts`. No personal data in
  event properties.
- Every source file under `src/core` and `src/blocks` has a sibling `*.test.ts` unless
  `cf-saas-lint.json` exempts it.
